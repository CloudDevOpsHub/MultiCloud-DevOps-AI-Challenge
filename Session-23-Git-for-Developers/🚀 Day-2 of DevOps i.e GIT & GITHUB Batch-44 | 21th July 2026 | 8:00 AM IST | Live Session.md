Day-2 focused on understanding how Git and GitHub are used in real software development teams. The session started with a quick revision of Day-1, covering the difference between Git (Version Control System) and GitHub (Remote Repository), repository creation, cloning, staging, committing, and pushing code.
Vikas explained the complete Agile and Scrum workflow, showing how multiple developers work together on the same project without overwriting each other's code. Students learned how developers create feature branches, work independently, push code to GitHub, raise Pull Requests (PRs), and get their code reviewed before merging into the main branch.
The session included live demonstrations of:
Creating repositories
Branch creation
Commit and Push workflow
Pull Requests (PR)
Code Review Process
Merge Process
Merge Conflicts
Git Pull & Git Fetch
Rebase
Squash Merge
Fast Forward Merge
Git Tags
Main vs Master Branch
Branch Naming Best Practices
Real-world company workflows were explained, including how developers use Jira ticket IDs while creating feature branches, how Tech Leads review code, and how CI/CD pipelines begin after successful code merges.
Students also discussed common Git issues like merge conflicts, reverting commits, deleting and restoring branches, cherry-picking commits, Git configuration, and collaborating with multiple developers on the same project.
The session concluded with practice assignments, LinkedIn posting, GitHub repository updates, and preparation for the upcoming Jenkins module.

## 🏢 10 Real-Time Scenario-Based Interview Questions

### 📌 Scenario 1

Two developers modified the same file. Your PR is showing a merge conflict.
> **❓ Question: How will you resolve it?**


### 📌 Scenario 2

You accidentally pushed buggy code to the main branch.
> **❓ Question: What steps will you follow to recover?**


### 📌 Scenario 3

Your teammate has already updated the main branch while you're working on a feature.
> **❓ Question: How will you synchronize your branch without losing your work?**


### 📌 Scenario 4

Your manager asks you to keep Git history clean with one commit instead of 15 commits.
> **❓ Question: Which Git feature will you use and why?**


### 📌 Scenario 5

A production issue occurred in Release v2.5.
> **❓ Question: How can Git Tags help identify and restore the correct release?**


### 📌 Scenario 6

You mistakenly committed confidential credentials to Git.
> **❓ Question: What actions would you take immediately?**


### 📌 Scenario 7

A developer accidentally deleted a branch that contained important work.
> **❓ Question: How can the branch or commits be recovered?**


### 📌 Scenario 8

Your Pull Request has been rejected during code review.
> **❓ Question: What should you do before requesting another review?**


### 📌 Scenario 9

Your project follows Jira-based development.
> **❓ Question: Why are branches commonly named like DEV-125-login-feature or PROJ-204-payment-api?**


### 📌 Scenario 10

A CI/CD pipeline failed immediately after merging your PR.
> **❓ Question: What would be your troubleshooting approach before escalating the issue?**
